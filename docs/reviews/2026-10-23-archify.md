## Concrete local gaps and acceptance

The previous UI review validator accepted missing baseline, component names and
journeys. It correctly warned that structural validity was not visual completeness;
the new readiness stage makes recorded prerequisites executable. Known inaccessible
areas can be `ready-with-gaps`; required records still block. The checker is read-only
and binds its report to the HTML bytes. External captures need separate inspection.

The previous Canvas proposal surface exposed proposed JSON and type migrations.
Comparison now derives changes from the captured pair, with no synthetic merged
architecture. Reviewing must preserve draft, navigation, history and saved bytes;
stale proposals remain inspectable and cannot Apply. Discussion proposals retain
the question and frozen comment targets/revisions in the review surface. Apply,
Save and feedback disposition keep their existing owners.

Validation uses CLI malformed-input and repair scenarios; model tests for identity,
position, reparenting, evidence and nonvisual entities; both proposal origins through
the browser harness; and compact-layout, focus-return and stale-basis checks.
Source/package verification is separate from installation and active Codex acceptance.
