What the audit found, and why the defects clustered

Baseline · source reviewed

The product cores are useful

Canvas shares document operations across HTTP and MCP. Reports reuse the same readers and renderers. Source revisions, draft saves and proposals already have meaningful contracts.

Keep these owners. A rewrite would discard working semantics.

Baseline defects · reproduced

Failures sit between owners

Polling evicted a send from inspection after ~64 seconds. Some model tools skipped the chat check. An orphan lock blocked recovery. Nested report data passed an incomplete validator.

These are boundary failures, not evidence that ordinary sessions always fail.

Architectural inference

Lifecycle rules lacked one home

Globals, caches, callbacks and adapters each carried part of the contract. The same authorization, retention or disposal rule could differ between routes.

The implementation moves these rules into shared owners and verifies their public boundaries.

Why an MCP App exists here: give the user direct control of a repository or report while sharing only explicitly selected context with the current conversation. The host is a transport and capability provider. Domain state remains owned by the app’s server modules.

Immutable contract; controlled mutable state

Fixed at creation

The declaration is a value

  • Instance ID, owner and transport mode
  • Protocol version and supported operations
  • Allowed transitions and capability policy
  • Retention budgets and disposal behavior

Copy and freeze plain definitions. Do not expose mutable Maps, callback setters or a mutable SDK object. A new declaration means a new instance or released contract version.

Changes only through commands

The owner makes each transition

  • Connection status and current generation
  • Draft revisions, report snapshots and requests
  • Observed send result; pending reads
  • Append-only observations within declared retention

Return detached snapshots. A closed instance stays closed. An old completion cannot publish into a new instance. Frozen configuration alone is not enough.

Interactive model · not a live host

A session has an explicit lifetime

Created→Connecting→Ready→ClosedFailure can also move Connecting → Unavailable or Incompatible.

Close aborts local reads and stops timers. A dispatched message with no acknowledgment remains uncertain. Close does not claim to cancel the host’s conversation turn.

Trace one user action through its owners

A plain message needs no source read. This example deliberately attaches one selected item.

Freeze the intent

The view submits exact text, draft revision and the selected item’s captured identity. One interaction ID begins here.

Resolve authority

The registry resolves the caller and context before any read or mutation. The domain owner creates a bounded selection.

Dispatch once

The host-session owner records the frozen request, then invokes the SDK. Child calls retain their own IDs under the interaction.

Observe and retain

Acknowledgment clears only the matching draft revision. Rejection or uncertainty keeps it. Background polls cannot evict this user action.

Representative contract shape
declareSession({
  protocol: 1,
  owner: { kind: "chat", id: "chat-A" },
  mode: "hosted",
  retention: { userActions: 40, background: 100 },
});

session.send({ interactionId, text, draftRevision, selection });
session.snapshot(); // detached, readonly state
session.dispose();  // terminal, idempotent

Implementation details owned by these modules
  • Validate operation inputs and outputs from canonical declarations; generate tool metadata where its actual contract is known.
  • Use typed errors for rejected, unavailable, stale, incompatible and uncertain outcomes. Keep diagnostic payloads out of ordinary model output.
  • Make polling single-flight, visibility-aware and abortable. State changes travel by revision; idle heartbeats stay small.
  • Use one App info surface with aligned labels, contextual interaction inspection and a bounded payload area. Preserve each report view’s scroll position.
  • Keep masking and metadata-only disk retention in the shared journal/store policy. Save payloads only for an explicit selected capture.
  • Bundle shared source into each plugin. Cover both packages and shared changes in CI. Keep the independently distributed starter as an explicitly pinned adaptation; check its receipt and generated-app CI.
  • Keep SDK 1.7.5 pinned for this change. A server SDK 2 migration is a separate compatibility decision.

Decisions settled with the user

The earlier recommendations and the three remaining decisions are accepted. Their consequences are now part of the implementation.

1 · Immutable contract per instance — accepted

Identity, ownership, declared capabilities, policy and callbacks are fixed. State changes through commands. Reconnect creates a new host session; the Canvas binding owner explicitly restores recoverable drafts.

A terminal lifetime cannot reopen. Host capabilities are copied after negotiation and returned as detached snapshots.

2 · Require hosted caller identity — accepted

Scoped tools reject missing or conflicting chat identity. Every context and frozen selection resolves through its owner. Standalone uses a trusted local principal chosen by its adapter.

Hosts must supply trusted threadId or thread_id metadata. This is an integration requirement, not a portable MCP guarantee. No unidentified shared-owner fallback exists.

3 · Separate prerequisite commit — accepted

The existing diagnostics feature was reviewed, tested in isolation and committed as e434aaa. This report and the architectural changes belong to the subsequent commit. Concurrent documentation cleanup 0adfdc5 remains a separate contribution.
